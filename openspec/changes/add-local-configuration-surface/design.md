# Design: Add Local Configuration Surface

## Absent from the published page, not hidden in it

The obvious implementation is one page that renders the editor and hides it when it is not being served
locally. It is the wrong one, and the reason is the difference between a page that does not show an editor
and a page that does not contain one.

Hidden markup is still markup. A published page carrying a disabled form and the script that would enable it
contains a script element and a form, which
`openspec/specs/flow-observability/spec.md:413` forbids outright, and anyone who opens the source can unhide
it. The constraint is not about what a viewer sees; it is about what the artifact is, which is why the
requirement is written as containment rather than visibility.

So the two surfaces are two artifacts from two commands. `telemetry board --html` renders the projection and
nothing else, exactly as today. The local surface is generated by the serving command and never written to
the path the published deployment uploads. A test asserts the published artifact contains no `<form>`, no
`<script>`, and no editing control, which is a stronger claim than the current no-script test and is the one
that keeps this split honest as both pages evolve.

## The loopback bind is the whole security model, and it is enough

The surface writes files with the permissions of whoever ran it, in the working copy they already own. It
needs no password because it grants no authority the shell they launched it from does not already have; what
it must never do is offer that authority to anyone else. Binding to the loopback interface and refusing any
other address is what makes that true, and it is checked rather than assumed.

There is no session, no token, and no account, because introducing one would imply the surface is reachable
from somewhere it must never be reachable from. A tool whose security story is "it is not on the network" is
stronger than one whose story is "it is on the network and asks for a password," provided the first claim is
enforced.

## It writes configuration and never records of what happened

The surface edits plan declarations and subscription cost records: what a plan is arranged to cost, and what
was paid. Both are operator-entered figures — nobody but a person knows them, which is why they are typed in
rather than derived.

It does not edit session records, the projection, or anything the harness wrote. Those are records of what
happened, and a web page that could edit them would make every figure downstream unfalsifiable. The line is
the same one `add-subscription-declarations` draws between a declaration and a record, extended to say which
of the two a person may revise from a browser.

## Not committing is the point, not an omission

The surface writes to the working copy and stops, so `git status` shows exactly what changed and the operator
reviews a diff before anything is history. This is deliberate symmetry with
`telemetry subscription close`, and with the reason that command does not commit either: a figure enters the
record when a person confirms it, not when a form is submitted.

It also means the surface needs no git authority at all, which keeps it outside every boundary this
repository draws around history.

## Optional, and provably so

The mechanism must keep working for anyone who never runs this. The projection, every read, the published
board, and the board workflow take no input from the surface and gain no dependency on it; it reads and
writes the same files the commands do, and adds no file kind of its own. `SHALL NOT require any workflow,
hosted service, message broker, database server, or platform API`
(`openspec/specs/flow-observability/spec.md:524`) stays true because _require_ is the operative word: a local
server an operator may run is not a service the mechanism depends on.
